# Presentation research for SAMStat 2.4

Scope: how QC results reach researchers. Recommendation first, evidence after.

## 1. Recommendation (minimal approach)

1. **One self-contained HTML file, no network.** Replace Plotly-from-CDN with static inline SVG generated by C code (~300-500 lines: a line plot, a bar plot, a stacked bar, a heatmap-free design). No JavaScript required to read the report. Optional 30-line inline JS for hover tooltips and a "copy table" button only.
2. **Fixed layout, same every time:** (a) header with file name, read type, counts; (b) a summary table of 8-10 rows with pass/warn/fail dots; (c) the plots in a fixed order; (d) a collapsible "How to read this plot" under each plot; (e) footer with version and command line.
3. **Few, conservative flags.** Only flag things that are almost always a real problem (very low mapped fraction, high unmapped, strong quality collapse, adapter-like length spike). Show flags as icon + word, never colour alone. Default to "info" not "fail" where library type matters.
4. **Long reads get the same layout, different binning.** Position axis in log-spaced or fixed 100-bin relative-position bins, plus a read-length histogram on a log axis with N50 marked. No per-base plots beyond a cap.
5. **Multi-sample = MultiQC, not a SAMStat feature.** Keep `--multiqc`/`--json`. Do not build a comparison view into the HTML. A single report may list several inputs as stacked sections with a sticky index, nothing more.
6. **Print: one CSS `@media print` block** (expand help, avoid page breaks inside figures, black-on-white). SVG makes PDF-from-browser vector and sharp.

## 2. What makes FastQC readable (evidence)

- Fixed module list, always in the same order, with a left-hand summary of pass/warn/fail icons. FastQC modules: basic statistics, per-base sequence quality, per-sequence quality, per-base sequence content, per-sequence GC, per-base N, length distribution, duplication, overrepresented sequences, adapter content. Source: https://www.bioinformatics.babraham.ac.uk/projects/fastqc/Help/3%20Analysis%20Modules/ (page fetch failed in this session; module list from memory, UNVERIFIED against the page).
- Each module has a doc page explaining "what good looks like" and "what to do". FastQC itself states that warnings/failures are heuristics and may be expected for some library types (e.g. RNA-seq composition bias, amplicons). UNVERIFIED by fetch; widely repeated in the module help.
- Known pitfall: the flags generate false alarms (per-base content on RNA-seq / bisulfite, duplication in high-depth or amplicon data, overrepresented sequences in small RNA). Users learn to ignore red. Lesson for SAMStat: fewer flags, thresholds documented, and a "why this is flagged" sentence next to each flag.

## 3. MultiQC lessons

- General Statistics table is the summary-first view; per-module columns configurable; conditional colouring defaults pass=green, warn=orange, fail=red, and fail wins when rules overlap. Source: https://docs.seqera.io/multiqc/reports/customisation (verified).
- MultiQC switches to flat (static) plots above a sample-count threshold and supports offline self-contained reports. NOT confirmed on the fetched page; UNVERIFIED (see https://docs.seqera.io/multiqc). Implication: the large-N use case is already handled downstream, so SAMStat's own HTML need not scale past one file.
- Keep our `_mqc` output stable and boring; that is the multi-sample story.

## 4. Offline HTML: embed vs CDN, library options

| Option | Size | Offline | Notes |
|---|---|---|---|
| Plotly 1.58.5 from CDN (current) | 0 in file | No | Fails on clusters/air-gapped, in review portals, in 5 years' time. |
| Plotly full inlined | plotly.js full minified 4.83 MB (current dist; 1.58.5 was ~3.5 MB, UNVERIFIED) | Yes | Every report 3.5-5 MB. Bad to email, slow to open, hundreds of reports = GBs. |
| Plotly basic/cartesian inlined | 1.2 MB / 1.51 MB | Yes | Source: https://github.com/plotly/plotly.js/blob/master/dist/README.md (verified). Still 1+ MB per report, needs a vendored blob and a version to track. |
| uPlot | ~50 KB, MIT | Yes | Source: https://github.com/leeoniya/uPlot (verified). Line/area/bars only; no heatmap/stacked-bar-native; needs JS. Good fallback if interactivity is required. |
| Vega-Lite | ~0.7-1 MB with vega + embed (UNVERIFIED) | Yes | Declarative but heavy; no gain over static SVG here. |
| **Static SVG from C** | 0 library; ~5-20 KB per plot | Yes, no JS | Chosen. Works in email previews, printing, archiving. Loses zoom/pan (rarely used for QC). |

Why SVG fits: our plots are 6-10 fixed types (lines with per-MAPQ series, bars, stacked bars). Series length is bounded by binning, so SVG stays small. Removes the 100 MB JSON-in-HTML failure mode for long reads, because the report holds only binned values. Add `<title>` per point for native browser tooltips (zero JS).

Risks: more C code for axes/ticks/labels (mitigate: one small "nice ticks" helper, one plot primitive, golden tests on SVG text); text layout is manual. Alternative if the maintainer rejects hand-rolled SVG: inline plotly-basic (1.2 MB) and drop the CDN. Cost: size, but zero new drawing code.

## 5. Layout: summary-first

- Top: file, format, read type (short/long auto-detected), total reads, mapped %, MAPQ>=30 %, median length, N50 (long), mean/median Q. 
- Immediately below: one row of status dots per check with a one-line reason.
- Then plots. Order: read length -> base quality -> MAPQ distribution -> mismatch/ins/del profile by MAPQ (SAMStat's distinctive plot, give it the most space) -> base composition.
- Same-scale rule: fixed y-axes where meaningful (0-100 %, Q0-Q41) so reports are comparable by eye. Autoscale only counts.
- Each plot: title is the question ("How accurate are the mapped reads along their length?"), one-sentence caption, collapsible 3-line interpretation: good looks like X; bad looks like Y; common benign cause.
- A "Details" `<details>` section with raw tables for copy/paste.

## 6. Flags (traffic lights): rules and pitfalls

- Three states: OK / check / problem. Use shape + text (circle/triangle/square or "OK", "CHECK", "FAIL"), not hue alone.
- Thresholds in one table in docs/, one place in code; show the measured value next to the flag.
- Candidates that rarely false-alarm: mapped fraction below ~50 % (CHECK) / below ~10 % (FAIL), where reference should match; median base Q below Q20 (short) - for long reads choose Q10 (ONT) thresholds by technology UNVERIFIED, must come from the technology research notes; fraction MAPQ<10 above 30 %; truncated/empty input.
- Avoid: GC content, duplication, per-base composition flags (library-dependent, FastQC's worst offenders).
- Never FAIL on input-type-dependent metrics; show them as info.
- `--no-flags`-style option not needed; flags are advisory text only and do not change exit codes (keep 0/1/2 meaning I/O success).

## 7. Accessibility and colour

- Use the Okabe-Ito palette (8 colour-blind-safe colours): #E69F00 #56B4E9 #009E73 #F0E442 #0072B2 #D55E00 #CC79A7 #000000. Reference: Okabe & Ito 2008, https://jfly.uni-koeln.de/color/ (not fetched; UNVERIFIED URL content).
- MAPQ bins (4 series) need ordered, distinguishable colours: use a sequential blue ramp for MAPQ>=30 / 10-29 / <10 and grey for unmapped; add different dash patterns and direct end-of-line labels so grayscale prints work.
- R1/R2: solid vs dashed, not just colour.
- Min text 12 px, contrast >= 4.5:1 (WCAG AA, https://www.w3.org/TR/WCAG21/#contrast-minimum), SVG with `role="img"`, `<title>` and `<desc>` summarising the trend; also provide the data as a table in `<details>` for screen readers.
- Respect `prefers-color-scheme` only if cheap; light theme only is acceptable and prints correctly.

## 8. Print / PDF

- `@media print`: white background, hide nav, `details` forced open, `break-inside: avoid` on figures, A4 portrait, 2 plots per page. SVG prints vector. No PDF generator in SAMStat; users print from the browser.

## 9. What not to do

- No tabs, dashboards, plot toggles, theme switchers, in-report filtering, JS frameworks.
- No per-sample comparison inside the HTML.
- No interactive zoom requirement.
- No external fonts: system font stack.
