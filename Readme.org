* SAMStat

SAMStat is an efficient C program to quickly display statistics of large
sequence files from next generation sequencing projects. When applied to SAM/BAM
files all statistics are reported for unmapped, poorly and accurately mapped
reads separately. This allows for identification of a variety of problems, such
as remaining linker and adaptor sequences, causing poor mapping. Apart from this
SAMStat can be used to verify individual processing steps in large analysis
pipelines.

SAMStat reports length distribution, base quality distribution, mapping
statistics, mismatch, insertion and deletion error profiles. The output is a
single html page:

[[Image of example output][https://user-images.githubusercontent.com/8110320/175869206-6edcb06d-1afc-42f6-bbb8-16a2a18146f0.png]]

* How to install

*SAMstat* needs autoconf/automake and zlib headers to build the bundled htslib. To install on linux:

Ubuntu/Debian:

#+begin_src bash :eval never
sudo apt-get install -y autoconf automake zlib1g-dev
#+end_src

On a mac via [[https://brew.sh][brew]]:

#+begin_src bash :eval never
brew install autoconf automake
#+end_src

To build *SAMstat* (=--recursive= is required: the tld library is a git submodule):

#+begin_src bash :eval never
git clone --recursive https://github.com/TimoLassmann/samstat.git
cd samstat
cmake -S . -B build
cmake --build build -j4
(cd build && ctest --output-on-failure)
cmake --install build
#+end_src

Optional CMake options: =-DSAMSTAT_USE_SYSTEM_HTSLIB=ON= (use the system htslib >= 1.16 instead of the bundled one), =-DSAMSTAT_SANITIZE=ON= (AddressSanitizer and UBSan) and =-DSAMSTAT_REQUIRE_MULTIQC=ON= (fail to configure if =multiqc= is missing, so the MultiQC integration test always runs).

Some memory errors only show up in a sanitizer build, so before a release also run the whole suite with it:

#+begin_src bash :eval never
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DSAMSTAT_SANITIZE=ON
cmake --build build-asan -j4 && (cd build-asan && ctest --output-on-failure -j4)
#+end_src

If you already cloned without =--recursive= run =git submodule update --init --recursive=.

* Usage

#+begin_src bash :eval never 
samstat <file.sam>  <file.bam>  <file.fa>  <file.fq> ...  <options> 
#+end_src

Input type (SAM, BAM, FASTA or FASTQ, plain or gzip) is detected from the content. A file name of =-= reads standard input; its reports are named =stdin.samstat.*=. Protein FASTA is not supported. For each input file SAMStat will create a single html page named after the input file name plus a dot =samstat.html= suffix. Exit codes: 0 success (also for inputs without reads, with a warning), 1 at least one input failed, for example an unrecognised input (the others are still processed), 2 usage error.

The output is identical for any =-t=. With at least as many inputs as threads, each input runs on its own thread; with fewer, the threads are shared within each input.

Available options:

#+begin_src bash :eval never 
  -d, --dir DIR      write reports to DIR (created if missing) [next to input]
  -p, --peek N       analyse only the first N reads (not random) [all]
  -t, --threads N    total threads; also speeds up a single input [4]
      --json         also write <input>.samstat.json (see docs/json-format.md)
      --multiqc      also write MultiQC files <input>.samstat_*_mqc.json (see docs/multiqc.md)
      --verbose      debug output
  -h, --help / -v, --version
#+end_src

=--nthreads= is accepted as an alias of =--threads=. The options =-l=, =--seed=, =--norm= and =--plotend= are deprecated: they are still accepted, print a warning and are ignored.

Before reading any input SAMStat checks that every report can be written. If a report directory is not writable that input fails (exit code 1) and the message suggests =-d DIR=. Two inputs that would write the same report file are a usage error (exit code 2).

* The report

The report is one self-contained HTML page: no JavaScript, no network request, and it prints to A4. It has a header line, a summary strip (reads, bases, N50, mean Q and, for aligned input, % mapped, % MAPQ >= 30, % bases clipped and median identity), a few factual notes where they apply, and, for aligned input, a table of the four MAPQ classes that is also the key for every coloured line. Then come six plots in a fixed order, each with a question as title, a one-sentence caption, a visible "Good:" line and a collapsed "How to read plot N":

1. How long are the reads? Read length distribution with N50.
2. How good is each read? Distribution of per-read mean base quality.
3. Where along the read does quality drop? Mean quality by position.
4. Is base composition even along the read? A, C, G, T and N by position.
5. Where along the read do errors occur? Mismatch, insertion and deletion rates by position (aligned input only).
6. How accurate are the aligned reads? Distribution of per-read identity (aligned input only).

Lines are coloured by mapping-quality class; paired input shows Read 1 and Read 2 side by side. Positions are in base pairs for short reads and in percent of read length when the median length is 1 kb or more. Unaligned input (FASTQ, FASTA, unaligned BAM) shows plots 1 to 4 only. A plot that cannot be drawn, for example mismatches for a BAM without MD tags, is replaced by a one-line note. bwa-mem and bwa-mem2 write MD tags by default; STAR and minimap2 (without =--MD=) do not.

* New in 2.4.0

- Intra-file threading: =-t= is the total thread budget and speeds up a single input.
- The HTML report is rebuilt with six fixed plots as inline SVG, and works offline.
- JSON format version 2 (breaking), a reworked MultiQC output, standard input, and content-based input detection.
- Protein FASTA is unsupported; =-l=, =--seed=, =--norm= and =--plotend= are ignored.

See =CHANGELOG.md= for the full list of changes and breaking changes.

* New in 2.3.0

- =--json= : machine-readable summary of the statistics (for pipelines and downstream tools).
- MultiQC support: SAMStat output can be aggregated by [[https://multiqc.info][MultiQC]] (see =docs/multiqc.md=, option =--multiqc=).

See =CHANGELOG.md= for details.
